# GaugeVision AI на Tilda

Версия сайта для Tilda собирается из `site/` скриптом `build.mjs`. Источник кода, текстов и стилей один —
`site/`; файлы в `dist/` генерируются, руками их не правят.

Проект Tilda «GaugeVision» (7124340), страница 409200509, адрес `gaugevs.tilda.ws` (страница назначена главной,
поэтому открывается и по корню, и по `/gaugevision`). Номера блоков — `records.json`, проверки — `checks.md`.

## Как устроено

Сайт строится на клиенте: `page.js` собирает листы из `GV.content`, модули листов монтируют интерактив.
На Tilda то же самое разнесено по Vibe-блокам (tplid 1370), каждый лист — свой блок:

| Где | Что |
|---|---|
| код `<head>` страницы (`dist/head.html`) | `theme-color`; скрипт до первой отрисовки (класс `html.gvt-page`, настройки Tweaks); `@font-face`; общий CSS: токены, база, движение, каркас листа, прибор; CSS уровня страницы |
| блок 01 `lib` (невидимый) | общие тексты (`meta`, `sections`, `labels`, `calibration`, `reading`), `util`, `motion` |
| блок 02 `top` | `kit` и сборщик страницы `src/runtime.js`, ссылка «К содержанию», `<noscript>`; шапку бланка и ярлыки листов строит `GV.tilda` |
| блоки 03–10 | восемь листов: тексты листа (JSON из `content.js` после типографа), CSS листа, модуль из `site/js/components/` |
| блок 11 `foot` | футер |
| блок 12 `tweaks` | панель Tweaks: масштаб и сорт бумаги, видит только автор (адрес с `?tweaks`) |

Блоки 01 и 02 должны стоять первыми: их скрипты нужны всем листам.

Почему так, а не иначе:

- Код передаётся в Tilda MCP текстом одного вызова, поэтому каждое поле держится в пределах ~37 КБ.
- Код `<head>` проекта Tilda сохраняет только у аккаунта с подтверждённой почтой, поэтому всё общее — в коде
  `<head>` страницы и в двух первых блоках.
- Каждое правило CSS получает префикс `.gvt` (класс корня любого блока). Порядок правил и файлов сохранён.
  `ledger.css` поделён между листами 05, 07 и 08 по классам-владельцам; правила листов не пересекаются,
  поэтому каскад тот же, что на `site/index.html`.
- Правила `html` и `body` из `base.css` (масштаб Tweaks, линовка бумаги, красное поле, выделение, скроллбар)
  работают только с классом `html.gvt-page`. Его ставит скрипт в `<head>` везде, кроме редактора Tilda.
  У блоков нет фона: линовка бумаги идёт по `body` через всю страницу, как в оригинале.
- Блок в конце своего скрипта зовёт `GV.tilda.boot()`. На опубликованной странице все блоки монтируются
  одним проходом на `DOMContentLoaded`, как в `page.js`. В редакторе Tilda анимации сразу в конечном состоянии.
- Липкие сцены листов 02 и 04 закреплены внутри своей секции: обёртки Tilda их не ломают.
- У блоков включён `animationoff` (иначе Tilda прячет блок до прокрутки), у листов — якоря `#hero` … `#contact`.

## Пересобрать и загрузить

```
node tilda/build.mjs          # dist/ с адресами CDN
node tilda/build.mjs --local  # dist/local/ с файлами из site/assets — открыть dist/local/emulation.html
```

`dist/emulation.html` — страница со стилями Tilda (`emu/`) и обёртками записей, как на опубликованной странице.
По ней сверяется перенос до загрузки.

Загрузка через Tilda MCP (номера блоков — `records.json`):

1. `update_page_head_code` — содержимое `dist/head.html` целиком.
2. Для каждого блока из `dist/manifest.json`: `update_record`, `tab="content"`, `only_field="code"`,
   `fields={"code": <файл>}`. Ответ должен быть ровно `OK`.
3. `publish_page`.

После правки `site/` пересобрать и записать заново только изменившиеся блоки: сравнить md5 файлов `dist/`
до и после сборки.

Тонкость канала: в параметрах вызова последовательность `\uXXXX` раскрывается в сам символ. В коде сайта
`\u` стоят только внутри строк и классов символов, поэтому это эквивалентная запись; сверка (`checks.md`)
приводит обе стороны к символам.

## Редактирование в Tilda

Тексты листа лежат в начале его блока, в объекте `part`. Правка в Tilda расходится с `site/`: чтобы
изменение не потерялось при следующей сборке, перенесите его в `site/js/content.js`.

# 0003. Код главнее README, а метрики публикуются как заявленные

## Контекст

README и PRODUCT.md были единственным заявленным источником фактов. Разбор кода показал 15 расхождений: роль Hough в поиске стрелки, область применения CLAHE, таймаут смартфона, третья маска по насыщенности, допуск калибровки за шкалу. Тестов, датасета и бенчмарков в репозитории нет, поэтому замеры из README воспроизвести нельзя.

## Решение

Описание конвейера, констант и ограничений пишется по коду. Если код и README расходятся, сайт следует коду. Метрики качества и скорости (0,38 %, mAP₅₀ 90,1 %, 7,2 мс и др.) публикуются как заявленные в README, каждая с условиями замера. Утверждения, которые код не подтверждает, не публикуются: «34 проверки e2e и 18 браузерных» и «ответ сервера 3–37 мс».

## Почему

- Принять README как истину отвергнуто: инженер станции, открыв код, увидит, что сайт приписывает CLAHE защиту от бликов в масках стрелки, а Hough назван равноправным методом. Одна найденная неточность обесценивает все цифры.
- Выбросить все метрики, которые нельзя воспроизвести, отвергнуто: бриф прямо требует полосу подтверждённых метрик, а замеры стенда — единственная количественная опора страницы.
- Публиковать «34 проверки» и «3–37 мс» отвергнуто: тестов в репозитории нет, а 37 мс — это RTT в браузере смартфона, и значение 3 мс нигде не подтверждено.
- Расхождение просто убрать из текста отвергнуто: молчание про CLAHE оставило бы без ответа вопрос про блики, а честный ответ («только при поиске циферблата») полезнее.

## Последствия

- Сайт и README расходятся в формулировках, и автор вынужден либо принять это, либо править README: исходные заявления остаются вне контроля сайта.
- Автоматическая проверка сверяет числа с README, PRODUCT.md и конфигурацией, но не проверяет контекст мелких чисел, поэтому часть защиты держится на ревью.
- Метрики качества остаются недоказуемыми из репозитория; на сайте они подписаны как стендовые, расчётные или оценка команды, и это снижает силу заявления.
- Любая правка кода, меняющая константу, молча делает сайт неверным, потому что связи между кодом и данными сайта нет.
- В разборе ограничений часть строк получает статус «частично», а не «реализовано» (копоть, автоалерт при загрязнении стекла).

# 0001. Статика на классических скриптах, без сборки и сети

## Контекст

Сайт должен открываться двойным кликом по `index.html` и работать на любом статическом хостинге. PRODUCT.md фиксирует «Статика HTML/CSS/JS», сам продукт работает офлайн, окружение не даёт ни конвертеров изображений, ни гарантии доступа к CDN.

## Решение

Сайт собран из чистых HTML, CSS и JS. Скрипты классические, подключаются тегами `<script src>` в фиксированном порядке и дописывают общий объект `window.GV`. Все пути относительные, шрифты лежат локально, размеры заданы в `rem`. Единственная проверка — `node` без зависимостей.

## Почему

- ES-модули отвергнуты: по `file://` браузер их не загружает, а открытие с диска — главное требование жюри.
- Фреймворк со сборкой (npm, бандлер) отвергнут: жюри получило бы папку, которую нельзя открыть без шага сборки, а PRODUCT.md прямо требует статику.
- Шрифты и библиотеки с CDN отвергнуты: сайт перестаёт работать офлайн, как и сам продукт, а правило «без CDN» проверяется механически.
- Свои конвертеры изображений отвергнуты: их нет в окружении, поэтому кадрирование делает CSS-обёртка над исходными скриншотами.

## Последствия

- Порядок подключения скриптов становится скрытым контрактом: перестановка файла ломает страницу без внятной ошибки.
- Глобальное пространство имён без модулей не защищает от коллизий, дисциплина держится на соглашении «один файл — одна IIFE».
- Нет минификации, тришейкинга и типов; вес шрифтов (пять семейств, кириллица и латиница) растёт вместе с числом вариантов.
- Любая зависимость придётся вручную копировать в репозиторий.
- Размеры в `rem` — обязательное правило: пиксели допустимы только для линий и медиазапросов, иначе масштаб Tweaks сломается.

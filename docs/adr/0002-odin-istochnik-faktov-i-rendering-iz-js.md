# 0002. Один источник фактов и рендер страницы из JS

## Контекст

Бриф требует три принципиально разных варианта страницы с одним и тем же набором экранов и запрещает выдумывать цифры. Три копии разметки с хардкодом разошлись бы в числах, а проверку честности пришлось бы делать глазами.

## Решение

Все тексты и числа лежат в одном объекте данных. `index.html` остаётся оболочкой: студийная панель, пустой корневой контейнер, Tweaks, `noscript`. Каждый вариант целиком рендерит страницу в корень из этих данных и из общих интерактивных компонентов, которые написаны один раз. Варианты выбирают раскладку компонента опцией и перекрашивают его своим CSS, но новых фактов не добавляют.

## Почему

- Три статических HTML-файла отвергнуты: факты разъезжаются между вариантами, а механическая проверка «каждое число есть в README» невозможна без единого места, где числа лежат.
- Отдельная реализация интерактива в каждом варианте отвергнута: калибровка, EMA-симуляция и разбор конвейера были бы написаны трижды, и исправная работа с клавиатуры не гарантировалась бы во всех.
- Подстановка данных в готовую разметку на сервере отвергнута: сервера нет, сайт открывается с диска.

## Последствия

- Без JavaScript страница пуста, поэтому нужен отдельный `noscript` с названием, одной фразой и ссылкой на GitHub; полноценной версии без JS нет.
- Итоговое число метрики приходится класть в DOM сразу, иначе читалки и поисковики его не увидят; анимация счётчика остаётся только визуальной.
- Компонент не владеет цветами и шрифтами, поэтому любое отличие вариантов приходится выражать токенами и раскладочными опциями. Если вариант захочет иную структуру компонента, придётся менять общий компонент и пересматривать два других варианта.
- Подписи интерфейса живут в локальных объектах компонентов, а не в данных: проверка фактов их не видит.
- Ограничение интерфейса данных: поля можно добавлять, переименовывать нельзя, иначе ломаются все три варианта.

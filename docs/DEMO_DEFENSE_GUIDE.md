# Демонстрационный пульт GaugeVision AI — инструкция запуска и проведения защиты

Документ описывает подготовку стенда, запуск профиля «Демонстрация», подключение смартфона Android и тайминг показа на защите проекта (2–3 минуты).

---

## 1. Архитектура демонстрационного стенда

На пульте отображаются **36 позиций приборов** с единой моделью данных:

- **Позиция №01 (`К1-Р01`, «Манометр острого пара К-1 (МТП-160)»)** — живой источник `phone_cv` («Камера телефона», структурная плашка `КАМЕРА`). Показания вычисляются серверным конвейером компьютерного зрения (`app/vision.py`) по реальным кадрам, поступающим со смартфона Android по защищённому каналу WSS (`/ws/phone/demo-mtp160-steam`).
- **Позиции №02–36 (`sim-02`…`sim-36`)** — синтетическая телеметрия `simulated` («Симуляция») по шести цеховым группам ТЭЦ. Значения рассчитываются детерминированным генератором (`app/demo.py`, 1 Гц) без создания камер, потоков видеозахвата и CV-воркеров, а также не попадают в таблицу истории и CSV живого прогона.

## 2. Установка зависимостей и запуск на ноутбуке

### Подготовка окружения (если виртуальное окружение ещё не создано)

По правилам репозитория (`AGENTS.md`):

```powershell
cd "C:\Hakatons\GaugeVisionAIDesign DashBoard"
py -3.12 -m venv .venv
.\.venv\Scripts\pip install torch torchvision
.\.venv\Scripts\pip install -r requirements.txt
```

На текущей машине все пакеты сервиса (`FastAPI`, `Uvicorn`, `aiosqlite`, `OpenCV`, `qrcode`, `cryptography`) уже доступны в системном `Python 3.12`, а веса `YOLOv8n` и пакет `ultralytics` — в `C:\C1\GaugeVS\.venv`.

### Быстрый старт профиля «Демонстрация»

Для защиты подготовлен скрипт, принудительно запускающий инференс на CPU (`CUDA_VISIBLE_DEVICES=""`, `--device cpu`), чтобы исключить нагрузку на дискретный мобильный GPU:

```powershell
cd "C:\Hakatons\GaugeVisionAIDesign DashBoard"
.\run_demo.cmd
```

Эквивалентная прямая команда:

```powershell
py -3.12 run.py --demo --device cpu
```

Если ноутбук подключён к нескольким сетям (Wi-Fi + VPN/виртуальный адаптер), укажите IP-адрес локальной сети явно, чтобы он попал в SAN сертификата и ссылку QR-кода:

```powershell
py -3.12 run.py --demo --device cpu --lan-ip 192.168.1.10
```

Также поддерживаются переменные окружения:

- `GAUGEVISION_DEMO=1` — включает демонстрационный профиль;
- `GAUGEVISION_DB` — путь к SQLite-базе (по умолчанию в демо-режиме создаётся отдельный файл `data/gaugevision_demo.db`, не затрагивающий повседневную базу `data/gaugevision.db`);
- `GAUGEVISION_DEVICE=cpu` — расчёт конвейера на центральном процессоре;
- `GAUGEVISION_LAN_IP` — переопределение локального IP для QR-кода;
- `GAUGEVISION_STALE_SECONDS=6.0` — порог свежести достоверного измерения.

## 3. Раскладка экранов, сеть и подготовка симулятора

1. **Режим дисплеев:** расширьте рабочий стол Windows (`Win + P` → «Расширить»).
   - **Внешний экран / проектор (1920×1080):** откройте пульт `https://localhost:8443` и переведите браузер в полноэкранный режим (`F11` или кнопка полноэкранного режима в правом верхнем углу шапки).
   - **Экран ноутбука:** откройте симулятор прибора `https://gaugevision-simulator.goodlyoatmeal32.chatgpt.site/`.
2. **Настройка симулятора перед показом:**
   - Выберите модель **«Манометр острого пара»** (`МТП-160`, `steam-pressure`), единица **МПа**, шкала **0–16**, круглая дуга **270°**.
   - Откройте **«Режим камеры»**, выберите светлый циферблат, прямой ракурс, выключите блик и наклон, поставьте минимальную инерцию и нулевую вибрацию стрелки.
   - В разделе **«Зоны и уставка»** отключите красную контрольную стрелку-уставку, чтобы в кадре оставалась одна чёрная измерительная стрелка. Верхние границы по умолчанию совпадают с пультом: предупреждение **14,2 МПа**, авария **15,2 МПа** (при включении двусторонних зон: нижняя предупредительная **4,0 МПа**, нижняя аварийная **2,0 МПа**).
   - Задайте начальное значение **13,0 МПа** (нажмите `Enter`) и сверните боковую панель настроек, чтобы геометрия прибора в кадре оставалась неизменной.
3. **Сеть и смартфон Android (проверить до выхода к жюри):**
   - Подключите ноутбук и смартфон к одной локальной сети Wi-Fi или раздайте точку доступа со смартфона / ноутбука (без изоляции клиентов AP Isolation).
   - Закрепите смартфон на устойчивой подставке напротив экрана ноутбука с симулятором.
   - Заранее один раз откройте ссылку захвата в Chrome на Android, примите самоподписанный HTTPS-сертификат («Дополнительно» → «Перейти на сайт») и разрешите доступ к задней камере.

## 4. Сценарий демонстрации на защите (2 мин 30 с — 2 мин 45 с)

При EMA-сглаживании (`α = 0,25`) и частоте обработки `3 к/с` стрелка проходит 90 % скачка примерно за **2,5–3 секунды**, а запись в SQLite идёт с шагом **1 отсчёт/с**. Удерживайте каждую контрольную точку **4–5 секунд**, чтобы в истории и CSV сохранилось несколько отсчётов в каждой зоне.

- **0:00–0:20 — Обзор установки (вкладка «Мониторинг»).**
  На внешнем экране открыта матрица `6×6` на всю ширину. Поясните жюри: на щите 36 позиций, 35 из них моделируют технологическое окружение ТЭЦ, а первая плитка `К1-Р01` с белой меткой `КАМЕРА` получает реальные показания с камеры смартфона. Покажите сводную строку статуса установки и отдельный индикатор телефона в шапке.
- **0:20–0:45 — Подключение смартфона по QR.**
  Нажмите кнопку `QR` в шапке (или откройте вкладку «Камеры»), отсканируйте код с экрана Android и нажмите «Начать трансляцию». Покажите смену статуса на «Показание получено» и появление числа `13,00 МПа` на плитке `К1-Р01`.
- **0:45–1:15 — Подтверждение настройки прибора (вкладка «Приборы и калибровка»).**
  Перейдите на вкладку «Приборы и калибровка». Покажите живой кадр со стрелкой, единицу `МПа`, опорные точки шкалы `0` (`135°`) и `16` (`45°`, по часовой стрелке, дуга `270°` с переходом через `0°`) и границы зон `H = 14,20 МПа`, `HH = 15,20 МПа`. Подтвердите или скорректируйте уставку, нажмите «Сохранить и открыть мониторинг», затем нажмите `Новый показ` в верхней полосе прогона, чтобы зафиксировать чистый старт записи.
- **1:15–2:05 — Прогон по зонам и квитирование.**
  1. На симуляторе введите **14,7 МПа** (`Enter`), выдержите 4–5 с: плитка `К1-Р01` и шапка переходят в янтарное состояние **«Предупреждение H»**.
  2. Введите **15,7 МПа** (`Enter`), выдержите 4–5 с: плитка окрашивается в аварийный красный (**«АВАРИЯ HH»**), в журнале фиксируется событие со стоп-кадром.
  3. Кликните по плитке `К1-Р01`, покажите справа живой кадр с векторной CV-разметкой и нажмите **«Квитировать»** в карточке прибора (или на вкладке «События»). Обратите внимание судей: мигание снято, ознакомление оператора записано, но аварийная красная зона сохраняется, пока давление физически не вернётся в норму.
  4. Введите на симуляторе **13,0 МПа** (`Enter`), дождитесь валидного возврата в норму (`Всё в норме (36 приборов)`).
- **2:05–2:45 — История прогона и выгрузка CSV (вкладка «История»).**
  Откройте вкладку «История» (по умолчанию выбран `К1-Р01` и текущий показ). Нажмите «Завершить показ», покажите график прогона с порогами, таблицу достоверных отсчётов и предпросмотр текста CSV. Нажмите **«Скачать CSV»**, откройте загруженный файл в Excel или текстовом редакторе и сверьте строки (`normal` → `warning` → `alert` → `normal`, метки ISO 8601 UTC, разделитель `;`, кодировка UTF-8 с BOM).

### Сокращённый и резервный маршруты

- **Если время ограничено:** подключите и прогрейте Android заранее до начала выступления; на шаге `0:20` кратко покажите окно с действующим QR-кодом (повторное открытие окна не сбрасывает токен и не обрывает активный поток) и сразу переходите к смене давления.
- **Если на защите кратковременно пропал поток (погас экран смартфона):** покажите честную реакцию пульта (`Нет свежих данных`, штриховка и сохранение последнего состояния без подмены синтетикой), разблокируйте экран Android и продолжите показ с той же карточки `К1-Р01`.

## 5. Отчёт о проверке и принятые инженерные решения

### Фактически проверено при разработке

1. **Конвейер компьютерного зрения (`app/vision.py`):**
   - Проверен на синтезированных кадрах циферблата МТП-160 (`1280×720`, шкала `0–16 МПа`, дуга `270°`, `135° → 45° CW`) по точкам `0,0`, `1,0`, `3,0`, `8,0`, `13,0`, `13,8`, `14,7`, `15,7` и `16,0 МПа` (включая переход через `0°/360°`).
   - Оба режима локализации работоспособны на CPU без участия дискретной видеокарты: классический конвейер OpenCV (`CLAHE + контурный эллипс`, `43–53 мс/кадр`) и гибридный `YOLOv8n + эллипс` на CPU (`75–116 мс/кадр`). Абсолютная погрешность снятия отсчёта на контрольных точках составила `0,002–0,019 МПа` (менее `0,15 %` диапазона шкалы).
2. **Серверные контракты и регрессионные тесты (`tests/test_demo_dashboard.py`):**
   - Проверены 36 стабильных ID, идемпотентность `POST /api/phone/session`, перевыпуск токена с принудительным закрытием старого WSS без смешивания кадров, отсутствие утечки токена в публичные маршруты.
   - Проверены граничные равенства `LL / L / H / HH`, отключение нижних зон (`lower_enabled=False`), блокировка равных и перевёрнутых границ (`422`), отсечка стрелки в мёртвой зоне при неверном направлении `CCW`, адресное идемпотентное квитирование `POST /api/events/{id}/ack`, связь записи возврата в норму с исходной аварией и фильтрация CSV по интервалу показа с сохранением совместимости старого `/api/cameras/{id}/export.csv`.
   - Автотесты маркетингового лендинга (`node site/tests/check.js` и `node site/tests/components.test.js`) проходят без замечаний.
3. **Браузерная сквозная проверка в Chromium (`playwright-core`):**
   - Выполнен полный прогон через реальный HTTPS-сервер Uvicorn и бинарный поток кадров WSS с проверкой разрешений `1920×1080`, масштаба `125 %` (`1536×864`) и экрана ноутбука `1366×768` (с полноразмерной карточкой прибора и кнопкой возврата). Ошибок консоли и необработанных исключений нет.

### Принятые обратимые решения

- **Изолированная БД демо-профиля:** при флаге `--demo` (или `GAUGEVISION_DEMO=1`) сервер автоматически работает с `data/gaugevision_demo.db`. Повседневная база `data/gaugevision.db` остаётся нетронутой.
- **Нижние зоны уставок МТП-160:** по умолчанию выключены (`lower_enabled: false`, активны `H = 14,2` и `HH = 15,2 МПа`), чтобы без лишних переключений совпадать со стартовым видом модели `steam-pressure` на сайте симулятора. Флажок «Двусторонние зоны» в разделе калибровки одним кликом подставляет штатные нижние границы `LL = 2,0` и `L = 4,0 МПа`.
- **Формат CSV:** используется кодировка `UTF-8` с BOM и разделитель `;`, корректно открывающийся в русскоязычном Microsoft Excel без мастера импорта; при смене шкалы или единицы во время активной записи сервер автоматически открывает новый интервал показа, не смешивая разные шкалы в одной таблице.

### Что обязательно проверить на живой репетиции перед защитой

Автоматический прогон выполнен с подачей сгенерированных JPEG-кадров по штатному маршруту `/ws/phone/{cam_id}` на одном узле. Перед выступлением необходимо провести минимум одну очную репетицию с секундомером на целевом стенде:

1. Прохождение трафика `HTTPS / WSS` на порту `8443` между реальным смартфоном Android и ноутбуком в выбранной Wi-Fi сети / точке доступа (отсутствие блокировки брандмауэром Windows и AP Isolation).
2. Загрузка внешнего сайта симулятора `https://gaugevision-simulator.goodlyoatmeal32.chatgpt.site/` на площадке выступления.
3. Отсутствие муара, полос ШИМ и бликов при физическом наведении камеры смартфона на экран ноутбука, а также читаемость шестого ряда матрицы на фактическом проекторе зала с дистанции жюри.

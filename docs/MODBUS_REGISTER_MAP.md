# Карта регистров Modbus TCP — GaugeVision AI (версия 2, редакция 3.0)

Документ описывает регистровую карту встроенного Modbus TCP-сервера GaugeVision AI (`app/scada_gateway.py`, класс `ModbusTcpGateway`) для интеграции с промышленными SCADA-системами (Ignition 8.3, MasterSCADA и др.) в режиме **только на чтение**.

---

## 1. Параметры подключения и протокола

| Параметр | Значение по умолчанию | Переменная окружения |
|---|---|---|
| Включение шлюза | Выкл (`0`) | `GAUGEVISION_MODBUS_ENABLED` (`1` для включения) |
| Адрес прослушивания | `127.0.0.1` | `GAUGEVISION_MODBUS_HOST` |
| TCP-порт | `15020` | `GAUGEVISION_MODBUS_PORT` |
| Unit ID (Slave ID) | `1` | `GAUGEVISION_MODBUS_UNIT_ID` |
| Поддерживаемые функции | `FC 0x03` (Read Holding Registers), `FC 0x04` (Read Input Registers) | Только чтение; функции записи отклоняются |
| Адресация в PDU | 0-базная (`0..5207`, `MAX_REGISTERS = 5208`; до версии 3.0 — `4096`) | В 1-базной нотации Modicon: `40001 + addr` |
| Порядок байт и слов (32-бит) | Big-endian (ABCD — старшее слово по меньшему адресу, старший байт первым) | IEEE-754 `float32`, `uint32` |
| Недостоверное / устаревшее значение | IEEE-754 quiet `NaN` (`0x7FC0`, `0x0000`) | Исключает подмену отсутствующего показания нулём `0.0` |
| Макс. регистров за один запрос | `1..125` | По стандарту Modbus TCP |

### Коды исключений Modbus

| Код | Значение | Условие возврата |
|---|---|---|
| `0x01` | Illegal Function | Любая функция, отличная от `0x03` и `0x04` (в т. ч. запись `0x06` / `0x10`) |
| `0x02` | Illegal Data Address | `start_addr + count > 5208` |
| `0x03` | Illegal Data Value | Неверная длина PDU либо `count < 1` или `count > 125` |
| `0x0B` | Gateway Target Device Failed to Respond | `unit_id != GAUGEVISION_MODBUS_UNIT_ID` |

## 2. Базовый блок приборов (v1, обратная совместимость)

Адреса `0..799` (1-базная нотация `HR 40001..40800`), до 200 приборов (`idx = 0..199`, базовый адрес `addr = idx * 4`). Раскладка и семантика **полностью сохранены** относительно версии 1.

С версии 3.0 `idx` — постоянный слот прибора `modbus_slot` из реестра (а не порядковый номер в списке): он закрепляется за прибором при регистрации, сохраняется в базе и не сдвигается при добавлении или удалении других приборов. Освобождённый слот и слоты без прибора во всех трёх блоках (базовом, расширенном, прогнозном) содержат `NaN` / `STALE` с момента запуска. Для существующих установок миграция назначает слоты по порядку создания источников (`cameras.created_at`) — в том же порядке версия 2.0 нумеровала приборы, поэтому привязки SCADA сохраняются. Проверено тестом `migration_from_real_old_code` (`tests/test_final_integration.py`) на базах, созданных кодом 1.0, 2.0 и обеих веток Next Gen; чтение таких адресов из SCADA на мигрированной базе отдельно не испытывалось.

| Смещение | 0-based адрес | 1-based HR | Тип | Описание |
|---|---|---|---|---|
| `+0..+1` | `idx * 4`, `idx * 4 + 1` | `40001 + idx*4` | `float32` BE | Текущее показание прибора в инженерных единицах; `0x7FC00000` (quiet `NaN`) при `STALE`/недостоверном отсчёте |
| `+2` | `idx * 4 + 2` | `40003 + idx*4` | `uint16` | Код статуса: `0` — OK (`normal`), `1` — WARNING, `2` — CRITICAL (`alert`), `3` — STALE / нет данных |
| `+3` | `idx * 4 + 3` | `40004 + idx*4` | `uint16` | Индекс технического состояния `Health Score × 10` (`0..1000`, т. е. `0,0..100,0 %`) |

В демонстрационном профиле (`--demo`, 36 приборов):
- `idx = 0` (`addr = 0..3`, `HR 40001..40004`) — `К1-Р01` (живая камера `phone_cv`, без телефона в состоянии `STALE`/`NaN`);
- `idx = 1..35` (`addr = 4..143`, `HR 40005..40144`) — 35 технологических позиций ТЭЦ (`К1-Т01` … `ТГ2-N01`).

## 4. Расширенный блок приборов (v2, база `2000`, шаг `8`)

Адреса `2000..3599` (1-базная нотация `HR 42001..43600`), до 200 приборов (`idx = 0..199`, базовый адрес `ext = 2000 + idx * 8`).

| Смещение | 0-based адрес | 1-based HR | Тип | Описание |
|---|---|---|---|---|
| `+0` | `ext + 0` | `42001 + idx*8` | `uint16` | `reading_age_s` — возраст последнего достоверного показания в секундах с насыщением `0..65535` (`65535` — достоверного показания ещё не было) |
| `+1` | `ext + 1` | `42002 + idx*8` | `uint16` | `confidence_x1000` — уверенность CV-распознавания × 1000 (`0..1000`; `0`, если для источника не определена) |
| `+2` | `ext + 2` | `42003 + idx*8` | `uint16` | `state_flags` — битовая маска состояния (см. таблицу ниже) |
| `+3..+4` | `ext + 3..4` | `42004 + idx*8` | `uint32` BE | `last_valid_unix` — Unix-время UTC (секунды) последнего достоверного показания (`0`, если не было) |
| `+5..+6` | `ext + 5..6` | `42006 + idx*8` | `float32` BE | `last_valid_value` — последнее достоверное значение (quiet `NaN` `0x7FC00000`, если не было) |
| `+7` | `ext + 7` | `42008 + idx*8` | `uint16` | `reserved` — резерв (`0`) |

### Битовая маска `state_flags` (`ext + 2`)

| Бит | Маска | Константа | Смысл при `1` |
|---|---|---|---|
| 0 | `0x0001` | `FLAG_CAMERA_ONLINE` | Камера / канал телеметрии на связи (`online` / `connected` / `simulated`) |
| 1 | `0x0002` | `FLAG_DIAL_DETECTED` | Циферблат / шкала обнаружены (или валидный источник) |
| 2 | `0x0004` | `FLAG_READING_VALID` | Текущее показание достоверно и конечно |
| 3 | `0x0008` | `FLAG_CALIBRATION_SET` | Задана невырожденная калибровка шкалы (`v_min != v_max`) |
| 4 | `0x0010` | `FLAG_IS_SIMULATED` | Источник является симуляцией демо-пульта (`0` — живая камера CV) |
| 5 | `0x0020` | `FLAG_CONFIDENCE_AVAIL` | В отсчёте присутствует численная уверенность CV |
| 6 | `0x0040` | `FLAG_READING_STALE` | Канал в состоянии `STALE` (нет свежих данных) |
| 7 | `0x0080` | `FLAG_ALARM_ACTIVE` | Активное нарушение уставки (`WARNING` или `CRITICAL`) |

## 4.1. Прогнозный блок приборов (Predictive Analytics, база `3600`, шаг `8`)

Адреса `3600..4087` (`HR 43601..44088`) — слоты `idx = 0..60`, `p = 3600 + idx * 8`. С версии 3.0 блок продолжен для слотов `idx = 61..199`: `p = 4096 + (idx - 61) * 8`, адреса `4096..5207` (`HR 44097..45208`). Адреса `4088..4095` не используются. Раскладка записи прибора в продолжении та же; адреса слотов `0..60` не изменились, поэтому существующие привязки Ignition работают без правок. Базу и первый слот продолжения SCADA может прочитать из `HR 916` и `HR 917`.

| Смещение | 0-based адрес | 1-based HR | Тип | Описание |
|---|---|---|---|---|
| `+0..+1` | `p + 0..1` | `43601 + idx*8` | `float32` BE | `eta_alert_min` — медианное время до аварийной уставки `HH`/`LL`, мин (`0.0` — уже пробита, `NaN` — нет прогноза) |
| `+2..+3` | `p + 2..3` | `43603 + idx*8` | `float32` BE | `eta_warning_min` — медианное время до предупредительной уставки `H`/`L`, мин (`NaN` — нет прогноза) |
| `+4` | `p + 4` | `43605 + idx*8` | `uint16` | Вероятность пробоя аварийной уставки на горизонте × 1000 (`0..1000`) |
| `+5` | `p + 5` | `43606 + idx*8` | `uint16` | Индекс аномальности тренда `anomaly_score × 10` (`0..1000`) |
| `+6` | `p + 6` | `43607 + idx*8` | `uint16` | Код класса тренда (`0=stable`, `1=rising_drift`, `2=falling_drift`, `3=accelerating_drift`, `4=oscillating_chatter`, `5=step_shift`, `6=insufficient_data`) |
| `+7` | `p + 7` | `43608 + idx*8` | `uint16` | Уверенность прогноза `forecast_confidence × 1000` (`0..1000`) |

## 5. Настройка в Ignition 8.3 (Modbus Driver v2)

При подключении к шлюзу GaugeVision в **Ignition 8.3** (`Modbus TCP` driver):

- **Hostname:** `127.0.0.1` (или IP edge-узла в изолированной технологической сети)
- **Port:** `15020`
- **Zero-Based Addressing:** `true` — позволяет использовать 0-базные адреса прямо из этой таблицы без смещения на 1 (`HRF0`, `HR2`, `HR900`, `HR906`, `HRUI907`, `HR2000`). При `false` (по умолчанию) к каждому адресу требуется прибавлять `+1` (`HRF1`, `HR3`, `HR901` и т. д.).
- **Reverse Word Order:** `false` — порядок слов в GaugeVision стандартный big-endian (старшее слово первым, `ABCD`), совпадает с настройкой драйвера Ignition по умолчанию.
- **OPC Item Path (при `Zero-Based Addressing = true` и имени устройства `GaugeVisionModbus`):**
  - Значение прибора `idx`: `ns=1;s=[GaugeVisionModbus]1.HRF{idx*4}`
  - Статус прибора `idx`: `ns=1;s=[GaugeVisionModbus]1.HRUS{idx*4+2}`
  - Health × 10 прибора `idx`: `ns=1;s=[GaugeVisionModbus]1.HRUS{idx*4+3}`
  - Системные регистры: `1.HRUS900` … `1.HRUS906`, `1.HRUI907` (uint32 `last_sync_unix`), `1.HRUS909`
  - Расширенный блок прибора `idx` (`ext = 2000 + idx*8`): `1.HRUS{ext}`, `1.HRUS{ext+1}`, `1.HRUS{ext+2}`, `1.HRUI{ext+3}`, `1.HRF{ext+5}`
- **Режим доступа тегов:** все теги в Ignition настраиваются с `readOnly: true` (или `accessRights: Read_Only`). Шлюз GaugeVision аппаратно не поддерживает запись (возвращает `0x01 Illegal Function`).

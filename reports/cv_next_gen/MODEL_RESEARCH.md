### 1.2. Фундаментальные причины ошибок CV v7/v8

Анализ `app/vision.py` и исторического отчёта `reports/industrial_validation/CV_VALIDATION_REPORT.md` показывает:

1. **Класс `1: Needle` не используется вообще.** `config.YOLO_CLASSES` фильтрует только `("gauge", "dial", "meter", "manometer", "clock")`. На проверочной подвыборке MeterFL dev (20 снимков) модель находит `Gauge` в 19/20 и `Needle` в 17/20, однако далее `app/vision.py` отбрасывает класс `Needle` и ищет стрелку исключительно классической морфологией OpenCV.
2. **Главная причина грубых ошибок — полярность стрелки при боковом свете (модель M1).** В `estimate_needle` маска `top-hat` (светлые объекты на тёмном фоне) отключается только при `face_level >= 140`. На снимках с боковым освещением медиана яркости поля попадает в диапазон 90–140, поэтому `top-hat` остаётся включённой и принимает блики стекла и светлые надписи за стрелку (74 из 77 грубых ошибок M1 на `final`, при 100 % верной локализации циферблата).
3. **Жёсткое предположение о центре вращения.** OpenCV всегда считает осью стрелки геометрический центр кропа `(320, 320)`. Смещение центра эллипса даже на 5–10 % радиуса порождает систематическую угловую ошибку.
4. **Деградация на плотном щите (N = 16).** При диаметре циферблата ~90 px в кадре `1280×720` модель `YOLOv8n` на входе `640` теряет ~10 % приборов, а `scale_arc_evidence` отвергает ~50 % отсчётов из-за размытия рисок.

## 4. Изучение готовых специализированных решений

### 4.1. ETH Zurich — Analog Gauge Reader (`ethz-asl/analog_gauge_reader`)

- **Статья:** *Under Pressure: Learning-Based Analog Gauge Reading In The Wild* (ETH Zurich ASL).
- **Архитектура:** 6 этапов — (1) YOLOv8 детекция корпуса, (2) замороженный DINOv2 + декодер тепловых карт для делений шкалы, (3) прямая аппроксимация эллипса по делениям (Halir/Fitzgibbon), (4) YOLOv8 сегментация стрелки + Orthogonal Distance Regression (ODR), (5) MMOCR + RANSAC для чисел шкалы, (6) пересечение прямой стрелки с эллипсом.
- **Проверка доступности весов:** официальный репозиторий GitHub (`ethz-asl/analog_gauge_reader`) **не содержит релизов и готовых предобученных весов** (`--detection_model`, `--segmentation_model`, `--key_point_model` пользователь обязан обучить и передать самостоятельно).
- **Лицензия:** код под **MIT**, но компоненты требуют YOLOv8 (AGPL-3.0) и MMOCR/DINOv2 (Apache 2.0, высокая нагрузка на CPU/VRAM).
- **Вывод для GaugeVision:** целиком конвейер не подходит (тяжёлые DINOv2 + MMOCR на CPU и отсутствие готовых весов, а автокалибровка OCR в GaugeVision 3.0 показала NG-AC-01 FAILED и отключена). Полезная заимствуемая идея — **пиксельная сегментация стрелки + ODR/PCA аппроксимация оси**.

### 4.2. Прочие специализированные решения

- **Cambridge RealGauges / SyntheticGauges** (*Howells et al., CVPRW*): 10 000 синтетических + 6 реальных приборов, разметка ключевых точек центра, кончика и границ шкалы. **Лицензия CC BY-NC 4.0** — запрещено коммерческое использование, поэтому не включается в обучающий набор коммерческого продукта.
- **P2-YOLO-Pose** (*Robust Analog Gauge Reading via Virtual Point-Based Geometric Rectification*): подтверждает эффективность P2-слоя (высокого разрешения) для мелких приборов и формулировки задачи через ключевые точки `(center, tip)`. В `ultralytics 8.4.183` аналогичная архитектура доступна из коробки (`yolo26-p2.yaml`, `yolo26-pose.yaml`).
- **VLM_gauge / IGVD** (`aMa2210/VLM_gauge`, Zenodo `20147961`, **CC BY 4.0**): открытый видеодатасет промышленных приборов. VLM-подход слишком тяжёл и неавтономен для промышленного edge-узла, но сам видеодатасет IGVD идеально подходит для независимой видеовалидации.

## 5. Стратегия экспериментов с учётом аппаратных ограничений

1. **Локально на CPU (выполняется в этой сессии полностью и воспроизводимо):**
   - Подготовка строгого разделения данных (`TRAIN / VAL / DEV / LEGACY / LOCKED FINAL`) и генератора синтетики.
   - Полный baseline `v3.0.0` на всех выборках.
   - Обучение и сравнение **компактных коммерчески чистых нейросетей определения стрелки на кропах 192×192**:
     - `NeedleKeypointNet` (Подход B2: координаты центра и кончика + `sin/cos` + видимость);
     - `NeedleSegUNet` (Подход C2: пиксельная сегментация стрелки и рисок + ODR/PCA);
   - Сравнение с улучшенной геометрией OpenCV (Подход A+), с неиспользуемым классом `Needle` из `gauge_yolov8.pt`, и с **Intelligent Fusion** (Подходы G/H).
   - Экспорт победившей модели в **ONNX** и проверка **ONNX Runtime CPU**.
2. **На внешней машине с Linux RTX 3090 24 ГБ (автономный воспроизводимый пакет `training_package_3090/`):**
   - Полное обучение и сравнение полнокадровых детекторов и single-stage моделей: `YOLOv8n` (retrain), `YOLO26n`, `YOLO26s`, `YOLO26s-p2`, `YOLO26s-pose`, `YOLO26s-seg`, `RF-DETR Nano`, `RF-DETR Small` на разрешениях 640 / 960 / 1280 с готовыми скриптами импорта весов обратно в `ModelRegistry` GaugeVision.

# Повторная проверка безопасности GaugeVision AI

Проверены `app/auth.py`, `app/security.py`, применение RBAC в `app/main.py` и поведение работающего сервера. Все испытания выполнены локально в изолированных временных каталогах. Итог: дефект DEF-07 устранён, в ходе проверки найдены и устранены четыре новых недостатка (NEW-04, NEW-10, NEW-11 и перепроверка SSRF при подключении). Остаточные риски перечислены в разделе 7.

Доказательства: `evidence/acceptance_tests/acceptance_results.json` (проверки `api_*`, `production_mode_*`), `evidence/interop/interop_results.json`, `evidence/browser_e2e/browser_e2e_report.json`, `evidence/offline_install/runtime_network_audit.jsonl`.

## 1. Аутентификация и хранение секретов

| Механизм | Реализация | Проверка |
|---|---|---|
| Пароли | PBKDF2-HMAC-SHA256, 120 000 итераций, соль 16 байт, сравнение `hmac.compare_digest` | Код `auth.hash_password` / `verify_password` |
| Сессии | Токен `secrets.token_urlsafe(32)`, в БД только SHA-256 токена, срок 12 ч | В таблице `sessions` нет открытого токена, есть его SHA-256 |
| Cookie | `HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS | Код `api_auth_login` |
| Выход | Удаление сессии из БД и cookie | После выхода REST → 401, открытый WebSocket закрывается кодом 4401 за ≤ 1 с (период перепроверки в тесте 0,5 с, штатно 15 с) |
| Истечение | `expires_at` в запросе сессии, ежечасная очистка истёкших (`prune_sessions`) | Код `db.get_session`, `_housekeeping` |
| Пароли RTSP | Fernet-шифрование URL с учётными данными в SQLite, маскирование `***:***@` в API, UI и журналах | Пароль не найден в 9 ответах API/WS, файлах SQLite (`main.db*`) и журнале; реальная RTSP-камера с паролем — 0 вхождений в API и журнале сервера |

### Стендовые учётные записи (NEW-04)

До повторной приёмки пароли `GaugeAdmin!2026`, `GaugeEng!2026`, `GaugeOp!2026` из `.env.example` действовали в любом режиме. Теперь вне деморежима:

- для новой учётной записи с пустым или стендовым паролем генерируется случайный пароль (19 символов), который однократно записывается в `initial_credentials.txt` рядом с БД (права 0600);
- вход со стендовым паролем отклоняется, даже если учётная запись была создана ранее в демо-БД.

Проверено отдельным процессом с `GAUGEVISION_DEMO=0`: файл создан для трёх ролей, стендовый пароль → 401, сгенерированный → 200, симуляция отказов администратором → 403.

### Защита от перебора (NEW-04)

Пять неудачных попыток для пары «имя + адрес» за 300 с блокируют вход с HTTP 429 и заголовком `Retry-After`, в том числе для верного пароля. Вход другого пользователя с того же адреса не блокируется. Попытки пишутся в журнал аудита (`LOGIN_FAILED`, `LOGIN_LOCKED`).

## 2. Ролевая модель

Роли упорядочены `operator < engineer < admin`. Из 64 адресов REST зависимость `require_role` стоит на 53; без неё остаются только страницы и значок (`/`, `/index.html`, `/capture`, `/capture.html`, `/favicon.ico`), вход и выход, `/api/auth/me`, `/api/health`, `/api/meta` и `/api/cert.pem`. WebSocket пульта требует сессию с ролью не ниже `operator`; WebSocket смартфона — одноразовый токен камеры, выданный инженером.

Проверенная матрица (HTTP-коды):

| Действие | operator | engineer | admin |
|---|---:|---:|---:|
| Добавление камеры | 403 | 201 | — |
| Симуляция обрыва АСУ ТП | 403 | 403 | 200 |
| Деградация видеосигнала | 403 | 403 | 200 |
| Сканирование подсети | 403 | 403 | — |
| Журнал аудита | 403 | 403 | 200 |
| Предпросмотр ТЗ | 403 | 200 | — |
| Досылка очереди | 403 | 200 | — |
| Автодокументы, диспетчерская сводка | 200 | — | — |
| WebSocket пульта | принят | — | — |

Без сессии все защищённые маршруты отвечают 401, WebSocket пульта закрывается кодом 4401. В браузере оператор видит пульт, а `POST /api/specs/generate` и `POST /api/architecture/outage` получают 403.

Повышение привилегий проверено двумя способами. Роль в сессии берётся из актуальной учётной записи: понижение роли инженера до оператора в БД сразу даёт 403, отключение учётной записи — 401. Подделать роль в токене нельзя: токен непрозрачен, в БД хранится только его хэш.

Симуляция отказов разрешена только администратору и только в деморежиме или при `GAUGEVISION_ALLOW_FAULT_INJECTION=1`.

## 3. SSRF

`validate_network_stream_url` разрешает частные сети RFC 1918/ULA и явно заданные `GAUGEVISION_ALLOWED_STREAM_CIDRS`. Всегда запрещены link-local и адреса метаданных облака, unspecified и multicast. Loopback и публичные адреса запрещены без явного флага.

Отклонены (HTTP 422) все 13 проверенных вариантов: `169.254.169.254`, `[::ffff:169.254.169.254]`, десятичная запись `2852039166`, `127.0.0.1`, `127.1`, `localhost`, `[::1]`, `0.0.0.0`, `metadata.google.internal`, публичный `8.8.8.8`, CGNAT `100.64.0.1`, схема `http://` для RTSP, `rtsp://[fe80::1]`. Принят адрес камеры в частной сети `192.168.1.10`.

Политика теперь перепроверяется при каждом подключении захвата, а не только при создании камеры. Это закрывает записи старых БД, принятые до введения проверки, и смену DNS-ответа после создания камеры. Остаточный риск — окно между проверкой и разрешением имени внутри FFmpeg (DNS rebinding с TTL порядка миллисекунд). Он снимается указанием камер по IP-адресам, как и принято в сетях АСУ ТП.

## 4. Path Traversal

`validate_video_file_path` нормализует путь через `Path.resolve()` и требует `is_relative_to(data/videos)` и видео-расширения. Отклонены (422): `..\..\Windows\win.ini`, `../../etc/passwd`, `C:\Windows\win.ini`, UNC `\\srv\share\a.mp4`, путь на другом диске `Z:a.mp4`, `sub/../../x.mp4`, имя с NUL, `notes.txt`, абсолютный путь вне каталога видео. Принят абсолютный путь внутри `data/videos` (сохраняется как относительный `bench.mp4`). Путь `C:bench.mp4` на том же диске нормализуется внутрь `data/videos` и выхода за каталог не даёт.

Скачивание автодокументов ограничено каталогом `auto_specs` той же проверкой `is_relative_to`.

## 5. Журналы, заголовки, ошибки

- NEW-10: access-лог uvicorn записывал полный путь WebSocket вместе с `?token=` — токен смартфона и сессионный токен. Добавлен фильтр журналов, маскирующий `token=`, `access_token=`, `api_key=` и учётные данные в URL. В интеграционном прогоне — 0 немаскированных токенов.
- Заголовки ответов: `Content-Security-Policy` (`default-src 'self'`, `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`. CORS только для явно заданных origin.
- Невалидные числа (`NaN`, `Infinity`) в запросах → 422 с корректным JSON, без HTTP 500.
- `/api/meta` до входа отдаёт только справочники для экрана входа, без пути к БД, адресов узла и состояния объекта.

## 6. Автономность

Аудит-хук Python в процессе сервера (события `socket.connect`, `socket.getaddrinfo`, `socket.sendto`, `urllib.Request`) за полный прогон запуска, инференса, генерации документов и Modbus зафиксировал 0 обращений к нелокальным адресам. До исправления NEW-11 ultralytics при импорте выполнял DNS-запросы к `one.one.one.one` и `dns.google`, а баннер `run.py` выполнял UDP `connect()` к 8.8.8.8 для выбора интерфейса (без отправки пакетов). В браузере за весь сценарий — 0 запросов вне узла. В интерфейсе есть одна внешняя ссылка — на онлайн-симулятор прибора для съёмки демонстрации (`<a target="_blank">`, адрес задаётся `GAUGEVISION_SIMULATOR_URL`); автоматических запросов она не порождает.

## 7. Остаточные риски

- Токен смартфона передаётся в строке запроса WSS (ограничение браузерного WebSocket API). Он одноразовый для камеры, перевыпускается кнопкой «Новый QR» и маскируется в журналах.
- Сертификат HTTPS самоподписный: для промышленного контура нужен сертификат из PKI предприятия.
- Блокировка перебора хранится в памяти процесса и сбрасывается при перезапуске.
- MQTT по TLS использует системное хранилище корневых сертификатов; отдельный параметр CA-файла брокера не реализован.

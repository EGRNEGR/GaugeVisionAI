# Безопасность объединённой версии: итоговый отчёт

Проверялся код ветки `next-gen/integration`. Источники: повторный прогон аудита Neon
(`reports/next_generation/evidence/security/run_security_audit.py`) на объединённом коде, проверки
`new_api_security` и `network_policy` в `tests/test_final_integration.py`, существующие наборы
`test_acceptance_independent` и `test_remediation_full`. Стенд локальный (TestClient, loopback); внешние системы
не затрагивались.

## 1. Повторный аудит Neon на объединённом коде

| Прогон | Итог | Доказательство |
|---|---|---|
| Как есть (граница карты 4095) | 10/11: SEC-10 не пройден | `evidence/security/security_audit_merged_before_boundary_update.json` |
| Граница карты = `MAX_REGISTERS − 1` | 11/11 | `evidence/security/security_audit_merged.json` |

Причина первого результата — продление прогнозного блока Modbus: адрес 4095 теперь внутри карты (5208 регистров).
Запись (FC 0x06 → 0x86/0x01) и чужой Unit ID (→ 0x83/0x0B) отклоняются как прежде; запрос через новую границу
даёт 0x83/0x02. В скрипте аудита граница взята из `ModbusTcpGateway.MAX_REGISTERS` — критерий не ослаблен.

## 2. Новые маршруты Multi-Gauge

| Запрос | Без входа | Оператор | Инженер | Администратор |
|---|---|---|---|---|
| `GET /api/sources/{id}/instruments` | 401 | 200 | 200 | 200 |
| `POST …/instruments/detect`, `POST …/instruments`, `PATCH /api/instruments/{id}` | 401 | 403 | 200/201 | 200/201 |
| `DELETE /api/instruments/{id}` | 401 | 403 | 403 | 204; основной прибор — 409 |

Некорректный ввод: шкала с `NaN` и вырожденная шкала — 422, имя длиной 5000 символов — 422, путь с `../` — 404.
Каждое изменение прибора пишется в `audit_log` (`CREATE_INSTRUMENT`, `UPDATE_INSTRUMENT`, `DELETE_INSTRUMENT`).

## 3. Замечания OBS-SHARED-01..05

Реализация — `app/net_policy.py`; поведение проверено `network_policy` и аудитом.

| ID | Было | Сделано | Состояние |
|---|---|---|---|
| OBS-SHARED-01 | веб-сервер на `0.0.0.0` без предупреждения | значение по умолчанию сохранено (смартфон-камера в ЛВС); вне демопрофиля — предупреждение при запуске; `GAUGEVISION_STRICT_NETWORK=1` запрещает запуск на всех интерфейсах | смягчено, строгий режим — закрыто |
| OBS-SHARED-02 | MQTT без TLS к любому брокеру | без TLS — только к брокеру на loopback; иначе нужен `GAUGEVISION_MQTT_TLS=1` (проверка сертификата и имени, свой УЦ через `GAUGEVISION_MQTT_CA_FILE`) или явное `GAUGEVISION_MQTT_ALLOW_PLAINTEXT=1` | закрыто |
| OBS-SHARED-03 | Modbus TCP без ограничения клиентов | вне loopback шлюз не запускается без `GAUGEVISION_MODBUS_ALLOWED_CLIENTS` (IP или CIDR); соединения с других адресов закрываются | закрыто |
| OBS-SHARED-04 | адрес LLM без SSRF-фильтра | только http/https, без учётных данных в адресе, без link-local и адресов метаданных; публичные адреса — только с `GAUGEVISION_LLM_ALLOW_PUBLIC=1`; при отказе ТЗ формируется детерминированно | закрыто |
| OBS-SHARED-05 | ссылка на внешний симулятор и зонд 8.8.8.8 | ссылка выдаётся только в демопрофиле; при заданном `GAUGEVISION_LAN_IP` зонд 8.8.8.8 не используется | закрыто |

Сохранено: доступ смартфона по ЛВС, работа без интернета, существующая система ролей и сессий.

## 4. Прочее

- Автокалибровка не может изменить калибровку: модуль не загружается сервисом даже с `GAUGEVISION_AUTOCAL=1`,
  маршрутов автокалибровки нет (проверено в отдельном процессе, `autocal_cannot_apply`).
- Внешних ресурсов в HMI нет: в браузерной проверке все запросы не к 127.0.0.1 блокировались и записывались —
  см. `OFFLINE_DEPLOYMENT_REPORT.md`.
- Не проверялось: внешний тест на проникновение, TLS с реальным промышленным брокером, межсетевой экран и
  сегментация реального объекта.

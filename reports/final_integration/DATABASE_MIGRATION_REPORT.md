# Миграция SQLite: отчёт

Миграции выполняет `app/db.py: init_db()` при каждом запуске: создание недостающих таблиц и индексов,
`ALTER TABLE … ADD COLUMN` по `PRAGMA table_info`, перестройка `cameras` под тип `video_file` для схем до 2.0,
заполнение `readings.instrument_id = camera_id` у старых строк и создание основного прибора для каждой камеры.
Строки не удаляются и не переписываются, кроме заполнения пустого `instrument_id`.

## 1. Базы, созданные кодом прежних версий

Проверка `migration_from_real_old_code` в `tests/test_final_integration.py`: код каждой версии извлекается
`git archive` во временный каталог и сам создаёт базу своим `init_db()`; затем в неё пишутся строки по фактической
схеме версии (камера, 120 отсчётов, 7 событий, паспорт и план — где такие таблицы есть), и база открывается
кодом объединённой ветки дважды подряд.

| Версия, создавшая базу | Таблиц до | Отсчётов до / после | Событий | Паспорт / план | Итог |
|---|---:|---|---:|---|---|
| консоль 1.0 (dd25bde) | 3 | 120 / 120 | — | — | PASS |
| GaugeVision 2.0 (94e646e) | 10 | 120 / 120 | 7 / 7 | — | PASS |

Во всех четырёх случаях: сумма значений `readings` до и после совпадает до 6 знаков, строк без `instrument_id`

## 3. Ревизия калибровки и история

- Колонка `readings.calibration_rev` (NULL у старых строк = ревизия 0) и `instruments.calibration_rev`.
- `get_instrument_series()` для приборов реестра отбирает только строки текущей ревизии; приборы вне реестра
  (стенд `instrument_readings`, удалённые приборы) не фильтруются. Проверено на живом многоприборном источнике:
  после ручной смены шкалы ряд прибора содержит только строки новой ревизии, ряды соседних приборов того же
  источника не затронуты (`multigauge_calibration_isolation`).
- Отсчёт, посчитанный по прежней шкале, пока инженер её менял, отбрасывается (DEF-INT-03) — иначе он попадал бы
  в ряд новой ревизии.

## 4. Идентификаторы

| Поле | Правило | Проверка |
|---|---|---|
| `instrument_id` | основной прибор = `cameras.id`, дополнительный — UUID v4 | `test_instruments_db`, `test_final_integration` |
| `gauge_slot` | уникален в пределах источника (`idx_instruments_gauge_slot`) | `test_instruments_db` |
| `modbus_slot` | уникален глобально, постоянен, освобождается при удалении; новый прибор занимает наименьший свободный | `modbus_slots_lifecycle`, шаг 19 сквозного испытания |
| `calibration_rev` | растёт только при изменении шкалы (не ROI и не уставок) | `autocal_cannot_apply`, `multigauge_calibration_isolation` |

## 5. Ограничения

- Заполнение `instrument_id` у строк без него выполняется при каждом запуске (`UPDATE … WHERE instrument_id IS
  NULL`); на больших архивах это полный просмотр таблицы при старте. На проверенных базах — доли секунды.
- Откат схемы (downgrade) не поддерживается: новые колонки и таблицы прежним кодом игнорируются, но перестройка
  `cameras` для схем до 2.0 необратима. Перед обновлением рабочей базы нужна резервная копия.

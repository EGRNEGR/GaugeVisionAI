# Известные ограничения GaugeVision AI 3.0

Перечень того, что не проверено, проверено частично или работает с оговорками. Ограничения не смягчались
ради итоговой оценки; каждое привязано к источнику.

## 1. Назначение системы

- GaugeVision AI 3.0 — инженерный прототип информационной системы. Он **не является** средством измерений
  утверждённого типа и не прошёл поверку; показания не могут использоваться для коммерческого учёта и
  метрологического контроля.
- Система **не является** системой противоаварийной защиты (ПАЗ) и не может входить в контуры
  блокировок. Тревоги и прогнозы — подсказка оператору; решение принимает человек по штатным приборам.
- Прогноз ETA — статистическая оценка тренда с интервалом, а не гарантия. События `prediction` не требуют
  квитирования и не заменяют уставки.

## 3. Прогноз и оптимизатор

- **Данные для прогноза по CV-прибору.** Ряд CV усредняется по корзинам 30 с (DEF-INT-13), модель требует
  не менее 6 точек — первый прогноз появляется примерно через 3 мин после начала записи или смены шкалы
  (новая `calibration_rev` начинает ряд заново).
- **Входной ряд CV.** Модель прогноза валидировалась агентом аналитики на рядах без EMA (1 с … 1 ч).
  Применимость к ряду CV после корзин подтверждена синтетическим тестом `cv_forecast_input` и сквозным
  испытанием на линейном дрейфе (ETA 11,1–11,9 мин при истинных 12,1–12,5). Нелинейный и ступенчатый
  дрейф на реальном видео не проверялся.
- **Расхождение документации (DEF-INT-12, открыт).** В `PREDICTIVE_REAL_DATA_VALIDATION.md` линейный режим
  описан как «R² ≥ 0,88», в коде дополнительно требуется автокорреляция остатков ρ₁ < 0,50
  (или t-статистика наклона ≥ 2,5 при ρ₁ < 0,35). Поведение определяется кодом.
- **Оптимизатор** решает 0-1 ILP за отведённое время (`time_limit_s`); точки кривой Парето, не уложившиеся в
  срок, помечаются `not_computed`. Цены, веса критичности и эффекты — исходные данные паспорта; их
  достоверность — ответственность инженера.

## 4. Интеграция с АСУ ТП

| Ограничение | Подробности |
|---|---|
| Ignition — пробная лицензия, один узел, loopback | Ignition 8.3.10 на том же компьютере (127.0.0.1:15020), пробный режим 2 ч. Многоузловая сеть, резервирование, промышленная лицензия не проверялись |
| Прогнозные регистры через Ignition — NOT VERIFIED | в проекте тегов Ignition нет тегов прогнозного блока, а учётных данных администратора шлюза для их добавления нет. Регистры проверены сторонним клиентом Modbus (шаг 11 сквозного испытания, `test_modbus_register_map`) |
| Имена тегов в Ignition — демонстрационные | теги `P01_K1_R01` … названы по демонстрационному профилю; сверка в сквозном испытании — по номеру слота, а не по имени |
| OPC UA в Ignition не проверялся | сервер OPC UA шлюза требует учётных данных, которых нет; доступ к данным проверен через Tag Historian и Perspective |
| Повторная сверка с Ignition после последних исправлений | см. `SCADA_REVALIDATION_REPORT.md`: что проверено на финальном коде, а что — на предыдущей сборке |
| Порядок слотов Modbus после миграции | слоты назначаются в порядке создания источников — как нумеровала приборы версия 2.0 (тест `migration_from_real_old_code`); на мигрированной базе в Ignition сверка адресов не выполнялась |
| Modbus TCP без аутентификации | свойство протокола; защита — режим только чтения, белый список адресов `GAUGEVISION_MODBUS_ALLOWED_CLIENTS`, сегментация сети |
| MQTT TLS | политика (запрет открытого MQTT вне loopback) проверена тестом `network_policy`; соединение TLS с промышленным брокером и собственным УЦ не испытывалось |

## 5. Эксплуатация

- Один процесс, одна база SQLite на узле; резервирование узла, кластер и горячая замена не реализованы.
- Самоподписанный сертификат HTTPS; на каждом устройстве его нужно принять или установить вручную.
- Веб-сервер по умолчанию слушает все интерфейсы (нужно для смартфона-камеры в ЛВС); для промышленной сети —
  `GAUGEVISION_STRICT_NETWORK=1` и явный адрес.
- Длительность непрерывных испытаний — 61,9 мин (`3714,9 с`, см. `SOAK_TEST_REPORT.md`) на 2 синтетических
  источниках (12 приборов: `video_file` + RTSP); многосуточная работа (≥ 72 ч), рост базы за недели и ротация
  архива не проверялись.
- Измеренные ограничения soak-прогона: на 4-й минуте (`t = 203 с`) зафиксирован единичный выброс задержки
  event loop (`loop_lag_max_ms = 1671,5 мс`, макс. задержка `/api/health = 1138,6 мс`) вне периодов обрыва
  и тяжёлой аналитики — предположительно пауза планировщика Windows или checkpoint SQLite WAL; в оставшиеся
  53+ минуты (`t > 520 с`) максимум окна не превышал 161,5 мс при медиане p95 = 19,5 мс. При обрыве издателя
  RTSP восстановление занимало 23,1–53,1 с (из-за экспоненциальной паузы и таймаута OpenCV/FFmpeg 6 с), что
  снижало общую долю годных отсчётов до 98,37 % за час.
- При одновременной работе CV-конвейера и оптимизатора на 500 позициях с кривой Парето (`probe_lag.py`)
  задержка event loop p95 составляет 37,9 мс (макс. 316,6 мс — влияние GIL в одном процессе Python на Windows);
  для жёстких SLA на парке > 300 приборов целесообразно выносить оптимизатор в отдельный процесс.
- Захват с USB-камеры и смартфона в этой приёмке не повторялся: `app/streamer.py` не менялся с версии 2.0
  (`git diff 94e646e` пуст), доказательство 2.0 перенесено с этой оговоркой; веб-камеру пользователя
  приёмка не включала.

## 6. Тесты

- `test_demo_dashboard` один раз не прошёл по таймингу (ожидание отсчёта после 6 кадров) и прошёл при
  повторах — см. `TEST_RESULTS.md` § 3. Плавающий тест зафиксирован, утверждения не ослаблялись.
- Ignition, mediamtx, amqtt, ffmpeg — внешние инструменты стенда; автоматические наборы их не требуют, а
  сквозное испытание и soak — требуют (`evidence/e2e/run_e2e.py`, `evidence/soak/run_soak.py`).

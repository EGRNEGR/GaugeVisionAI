# Отчёт о сквозном интеграционном испытании (19 шагов E2E)

Стенд: `evidence/e2e/run_e2e.py`. Отдельный процесс сервера `run.py` (HTTPS, CPU), сторонний MQTT-брокер `amqtt`,
подписчик `mqtt_sink.py`, шлюз Modbus TCP `127.0.0.1:15020` (Unit ID 1, read-only) и живой экземпляр SCADA
**Ignition 8.3.10** с чтением её Tag Historian (`samplequickstart.db`, только чтение).

> **Происхождение видеоисточника (синтетика):** используется синтетический видеофайл щита `panel_e2e.mp4`
> (`scripts/make_panel_video.py`: 8 аналоговых приборов в кадре 1280×720, 2 к/с; 7 приборов стабильны,
> прибор `PI-102` линейно дрейфует от 1,178 к 1,488 МПа за 20 мин). Это стенд проверки сквозной интеграции
> цепочки, а не видео действующего цеха; точность CV на реальных фото оценивается в `CV_VALIDATION_REPORT.md`
> и `MULTI_GAUGE_VALIDATION.md`.

## 4. Границы применимости вывода

Сквозное испытание подтверждает целостность программной цепочки **«видеопоток → Multi-Gauge CV → SQLite →
прогноз + события `prediction` → MQTT/S&F → Modbus TCP → Ignition 8.3.10 → ILP-оптимизатор → ТЗ DOCX/MD →
рестарт»** на финальном коде 3.0. Оно **не** заменяет полевую валидацию точности CV на цеховых камерах
(`REQ-CV-05`) и не подтверждает промышленную точность прогноза на скачкообразных/нелинейных реальных авариях (`NG-PA-01`).

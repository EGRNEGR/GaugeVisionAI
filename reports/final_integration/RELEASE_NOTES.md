# GaugeVision AI 3.0 — примечания к выпуску

Ветка `next-gen/integration` (кандидат в выпуск). Базовая версия — GaugeVision AI 2.0 (`94e646e`).
Релизный тег не создавался, слияния с `main` и `GaugeVision-2.0` не было — это решения владельца проекта.

Статус: инженерный прототип для лабораторной интеграции и ограниченного пилота — см. уровни готовности в
`FINAL_ACCEPTANCE_REPORT.md`. Не является средством измерений и не является системой ПАЗ.

## Новое

### Щит: несколько приборов на одном видеоисточнике (ветка `next-gen/platform`)

- Реестр приборов `instruments`: у каждого прибора свой `instrument_id`, `gauge_slot` на источнике, шкала с
  ревизией `calibration_rev`, уставки, постоянный слот Modbus `modbus_slot` 0…199.
- Один проход детектора на кадр, трекер якорей, по-приборные конвейеры; кнопка «Найти приборы на кадре».
- Вкладка пульта «Щит»: общий кадр источника с разметкой, таблица приборов, регистрация и удаление.
- Телеметрия приборов щита в MQTT (`{instrument_id}/telemetry`, не чаще раза в 5 с, только достоверные).
- Генератор синтетического видео щита для стенда (`scripts/make_panel_video.py`): постоянные значения или
  линейный дрейф с известной истиной.

### Прогноз и оптимизатор (ветка `next-gen/analytics-validation`)

- Прогноз по прибору: класс тренда, PI80 / PI95, ETA до уставок H / HH и вероятность пробоя на горизонте,
  индекс аномальности (`/api/predictive/*`, секция прогноза на вкладке «Диспетчеризация и ТЗ»).
- Оптимизатор плана модернизации: 0-1 ILP по бюджету с обязательными позициями, кривая Парето, сравнение с
  жадным выбором, сохранённые планы (`/api/optimizer/*`), раздел плана в ТЗ (.md, .docx).
- Паспорта приборов (класс критичности, стоимость) — `/api/passports`.
- Прогнозный блок Modbus (3600…4087), проект тегов и мнемосхема Perspective для Ignition 8.3
  (`integrations/ignition/`).

### Интеграция (ветка `next-gen/integration`)

- События прогноза `prediction`: переходы `imminent` / `cleared` / `realized` / `withdrawn` с порогами
  входа и выхода и подтверждением двумя расчётами — без дублей; в журнале, SQLite, на пультах, в MQTT
  (`{id}/alarm`, `kind = "prediction"`); квитирования не требуют.
- Прогнозный блок Modbus продолжен для слотов 61…199 (адреса 4096…5207, `HR 916` / `917`); адреса слотов
  0…60 не изменились.
- Прогноз берёт только отсчёты текущей `calibration_rev`; ряд CV-прибора усредняется по корзинам 30 с
  (`GAUGEVISION_PREDICTIVE_CV_BIN_S`) — устраняет запаздывание ETA на сглаженном ряде CV.
- Сетевая политика развёртывания (`app/net_policy.py`, замечания OBS-SHARED-01..05): строгий режим
  `GAUGEVISION_STRICT_NETWORK`, белый список клиентов Modbus, запрет открытого MQTT вне loopback, защита
  адреса LLM от SSRF, URL симулятора только в демопрофиле. Смартфон-камера в ЛВС и работа без интернета
  сохранены.
- Оптимизатор соблюдает общий срок `time_limit_s` (основная задача и кривая Парето); не уложившиеся точки
  помечаются `not_computed`, в ответе `elapsed_s` и `frontier_complete`.
- `/api/health` возвращает задержку event loop (`loop_lag_ms`: p50 / p95 / p99 / max за 5 мин).

## Исправлено при интеграции

Полный реестр — `DEFECT_REGISTER.md`. Главное:

| ID | Что было |
|---|---|
| DEF-INT-01 | при остановке кадров без разрыва соединения Modbus продолжал отдавать последнее значение со статусом OK |
| DEF-INT-02 | свободные слоты Modbus с запуска содержали 0,0 со статусом OK вместо NaN / STALE |
| DEF-INT-03 | кадр, обработанный во время смены шкалы, попадал в ряд новой ревизии |
| DEF-INT-04 | HR 905 не выставлялся при реальном отказе брокера MQTT |
| DEF-INT-05 | оптимизатор с кривой Парето превышал `time_limit_s` |
| DEF-INT-13 | ETA по ряду CV запаздывал в 2–3 раза на линейном дрейфе |
| DEF-INT-14 | код позиции основного прибора, заданный инженером, не применялся |

## Обновление с версии 2.0

1. Остановите сервис, сделайте копию `data/gaugevision.db` и `data/store_forward.db`.
2. Обновите код; зависимости не менялись (`requirements.txt`, `requirements.lock`, `Dockerfile` совпадают с
   `94e646e`), переустановка не нужна.
3. Запустите сервис: схема мигрирует автоматически и идемпотентно — добавляются таблицы `instruments`,
   `instrument_readings`, `instrument_passports`, `predictive_snapshots`, `modernization_plans`, у каждой
   камеры появляется основной прибор, история и события сохраняются (`DATABASE_MIGRATION_REPORT.md`).
4. SCADA: адреса базового, расширенного и прогнозного (слоты 0…60) блоков не изменились; слоты
   назначаются в порядке создания источников, как в 2.0. Прибор, которого нет, теперь виден как NaN / STALE.
5. Если MQTT-брокер или SCADA находятся не на этом узле, задайте `GAUGEVISION_MQTT_TLS=1` (или явно
   `GAUGEVISION_MQTT_ALLOW_PLAINTEXT=1`) и `GAUGEVISION_MODBUS_ALLOWED_CLIENTS` — без них новая сетевая
   политика не даст открыть небезопасное соединение.

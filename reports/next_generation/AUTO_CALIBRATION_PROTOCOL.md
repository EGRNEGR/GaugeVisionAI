# Auto Calibration — протокол испытаний и критерии допуска

Требование NG-AC-01. Документ фиксируется в git **до** реализации модуля и до любых прогонов;
критерии ниже после этого не меняются. Если модуль их не выполнит, автоматическая калибровка
не включается в основной продукт: остаётся экспериментальным модулем, отключённым по умолчанию,
с отчётом о результатах.

## 1. Что делает модуль

На входе — кадр и ROI циферблата (найденная автоматически или обведённая инженером). На выходе —
либо предложение калибровки `{v_min, theta_min, v_max, theta_max, direction}` в той же системе
углов, что `vision.angle_to_value`, с оценкой достоверности и обоснованием (найденные деления и
подписи), либо отказ с причиной. Предложение не применяется само: инженер подтверждает или правит
его в форме калибровки. Всё работает локально на CPU, без облачных сервисов.

## 2. Данные

- MeterFL (CC BY-SA 4.0), только круглые шкалы (`scope = round_dial`), записи с размеченными
  центром, первым и последним делением и значениями начала и конца шкалы
  (`reports/industrial_validation/data/dataset_manifest.json`).
- `dev` — 77 снимков, 8 моделей приборов: разработка и настройка.
- `final` — 201 снимок, 71 модель: **один** прогон после фиксации кода; по его результатам алгоритм
  не меняется.
- Синтетические циферблаты `app/panel_sim.py` используются только для модульных тестов и в метрики
  допуска не входят.

Изображения в репозиторий не попадают, публикуются только метрики.

## 3. Условия прогона

- Основной режим (критерии допуска): ROI задана так, как её обводит инженер, — окружность по
  размеченному центру и радиусу делений с ошибкой: сдвиг центра равномерно до 5 % радиуса,
  радиус ×U(0,90; 1,10), фиксированный seed.
- Дополнительный режим (отчёт, без критериев): ROI от автоматического детектора конвейера; если
  циферблат не найден — отказ.
- CPU: `CUDA_VISIBLE_DEVICES=""`, `GAUGEVISION_DEVICE=cpu`.

## 4. Метрики

Эталонная калибровка — первое и последнее размеченные деления (углы через ту же ROI) и значения
`scale_min`, `scale_max`. Для принятого предложения считается

    err = max |f_auto(θ) − f_ref(θ)| / (scale_max − scale_min)

по 50 равномерным углам θ рабочей дуги эталона; если `f_auto` на части дуги не определена
(угол вне дуги предложения), `err = 1`.

- покрытие — доля снимков, по которым предложение выдано (не отказ);
- точность — доля принятых предложений с `err ≤ 2 %`;
- грубые — предложения с `err > 10 %` (опасный случай: уверенно предложена неверная шкала);
- пределы — доля принятых, у которых `v_min` и `v_max` совпали с эталоном;
- время — медиана на один циферблат, CPU.

Дополнительно приводятся разбивка по моделям приборов, причины отказов и те же метрики для
дополнительного режима.

## 5. Критерии допуска в основной продукт (final, основной режим)

| № | Критерий | Порог |
|---|---|---|
| G1 | грубые от всех снимков / от принятых | ≤ 1 % / ≤ 2 % |
| G2 | точность среди принятых | ≥ 90 % |
| G3 | покрытие | ≥ 50 % |
| G4 | пределы шкалы среди принятых | ≥ 95 % |
| G5 | медиана времени | ≤ 3 с |

Все пять выполнены — модуль включается в продукт как «предложение калибровки» с обязательным
подтверждением инженером. Хотя бы один не выполнен — в продукт не включается.

# Отчёт о масштабируемости Modernization Optimizer (N = 36…1000)

**Проект:** GaugeVision AI Next Generation  
**Ветка:** `next-gen/analytics-validation`  
**Сравниваемые решатели:**
1. **`bnb` (собственный air-gapped итеративный Branch-and-Bound)** — 0 внешних зависимостей, `O(log n)` верхняя граница Данцига, многостартовая эвристика, жёсткий лимит `time_limit_s = 1.0 с`.
2. **`highs` (промышленный C++ MILP-решатель HiGHS 1.16.0 через `scipy.optimize.milp` 1.18.1)** — лимит `time_limit_s = 5.0 с`.

**Сырые данные:** `reports/next_generation/evidence/ilp/ilp_scalability.csv`, `ilp_verification_and_scalability.json`

---

## 1. Методика нагрузочного тестирования

Для каждого масштаба **N ∈ {36, 100, 250, 500, 1000}** сформированы 4 семейства задач (всего 20 независимых бенчмарков):
- **`typical_industrial`** — реалистичный портфель модернизации КИПиА (6 цехов, CAPEX 55–220 тыс. ₽, обязательные предписания ~7%, исключения, зависимости, взаимоисключающие альтернативы, квоты цехов).
- **`strongly_correlated`** — классическая трудная задача рюкзака ($u_i = c_i/1000 + 100$), плохо отсекаемая обычной LP-релаксацией.
- **`subset_sum`** — вырожденная задача ($u_i = c_i/1000$), где все элементы имеют одинаковую удельную полезность $u_i/c_i = \text{const}$.
- **`dense_constrained`** — плотные зависимости (20%), взаимоисключающие группы (33%), двусторонние квоты по 4 группам и жёсткий лимит `max_items = 0.45 * N`.

Замерялись: время решения (мс), пиковое потребление RAM (`tracemalloc`, КБ), число исследованных узлов, статус, доказанная верхняя граница (`UB`), `optimality_gap` (%) и фактическое отклонение от доказанного оптимума HiGHS (`err_vs_highs`, %).

## 3. Анализ и архитектурное решение

1. **Надёжность и память на масштабе `N = 1000`:** после перехода на итеративный стек оба решателя потребляют **≤ 1,02 МБ RAM** при `N = 1000`, не допускают переполнения стека, на **20 из 20 задач** возвращают 100% допустимое решение и математически валидную верхнюю границу (`UB >= true_opt`).
2. **Точность air-gapped BnB при лимите 1 с:**
   - На штатном масштабе одного энергоблока (**N = 36–100**, `typical_industrial` и `strongly_correlated`) собственный `bnb` доказывает глобальный оптимум за **3,1–160,6 мс** (при `N = 36 typical` быстрее HiGHS в **4,5 раза**: `3,13 мс` против `14,27 мс`).
   - На `N = 250–1000` без плотных зависимостей air-gapped `bnb` за 1 с находит решения в пределах **0,000%–2,33% от глобального оптимума** и честно сообщает `status = "time_limit"` и фактический `optimality_gap`.
   - На искусственно усложнённом семействе `dense_constrained` (`N ≥ 100`, сотни зависимостей + квоты + mutex) одномерная бюджетная релаксация даёт gap `10,5–13,3%` (фактическая ошибка `5,3–8,1%`).
3. **Объективное превосходство HiGHS при `N > 40`:** промышленный C++ MILP-решатель **HiGHS 1.16.0** (симплекс + отсекающие плоскости + presolve) доказывает глобальный оптимум (`gap = 0,000%`) на **19 из 20 задач** до `N = 1000` за **7,5–610,6 мс** (включая `dense_constrained N = 1000` за **303,2 мс**!).

**Принятое инженерное решение (`solver_backend = "auto"` в `app/ilp_solver.py`):**
- Сохраняется **100% автономная air-gapped работа** без внешних библиотек через итеративный `bnb` (базовая поставка `requirements.txt` не меняется).
- Если в промышленном контуре установлен опциональный пакет `scipy` (wheel-пакет в офлайн-репозитории), режим `solver_backend="auto"` автоматически использует `bnb` на малых задачах (`N ≤ 40`, где он быстрее за счёт отсутствия накладных расходов матрицы) и автоматически переключается на **HiGHS** при `N > 40`, обеспечивая доказанный оптимум для корпоративных парков на 250–1000+ приборов за доли секунды.

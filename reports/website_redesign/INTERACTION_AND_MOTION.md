# Взаимодействие и движение

## Принципы

1. **Движение объясняет, а не украшает.** Каждая анимация показывает процесс продукта: стрелка доходит до
   значения, пакет летит по каналу, область неопределённости разворачивается, плитка переезжает в план.
2. **Зритель делает сам.** В каждой секции возможностей 3.0 есть действие: переключатель, кнопка, ползунок,
   точка на экране.
3. **Только `transform` и `opacity`.** Свойства, вызывающие перерасчёт раскладки, не анимируются. Сознательное
   исключение — шторка «Задача»: `clip-path` и `left` ручки меняются только по действию пользователя. Нарушение,
   найденное приёмкой и исправленное: раскрытие описаний этапов истории меняло высоту колонки (CLS 0,79 на
   1440×900). Теперь все описания лежат в одной ячейке сетки, переключается только прозрачность — CLS 0,002.
4. **Один цикл кадра.** Все покадровые обновления идут через `GV.motion.onFrame` и `onScroll` из v2: один
   `requestAnimationFrame`, измерения отделены от записи. Симуляции работают, только пока секция видна
   (`IntersectionObserver`).
5. **Reduced motion — полноценная версия.** При `prefers-reduced-motion: reduce` переходы выключены, вместо ролика —
   постер без закрепления, ТЗ сразу собрано, закреплённые сцены переключаются мгновенно. Всё содержание доступно.

## Длительности и кривые (`tokens.css`)

| Токен | Значение | Где |
|---|---|---|
| `--dur-fast` | 160 мс | наведение, нажатие |
| `--dur-med` | 320 мс | смена описания этапа, плашки, переключатели |
| `--dur-slow` | 600 мс | переход прибора-героя между сценами, перестройка плана (FLIP) |
| `--dur-xslow` | 1000 мс | счётчики, сборка ТЗ |
| `--dur-crawl` | 1400 мс | появление первого экрана |
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | основная кривая: быстрый старт, мягкая посадка |
| `--ease-snap` | `cubic-bezier(0.2, 0.9, 0.1, 1.05)` | стрелка прибора с лёгким перелётом |

## Секции

| Секция | Взаимодействие | Движение | API для режима демонстрации |
|---|---|---|---|
| Первый экран | прокрутка | ролик идёт по кадрам за прокруткой (`scroll-video` из v2), панель этапов отмечает «Кадр камеры → … → Цифровой канал» | `hero.setProgress(p)` |
| Задача | шторка «Сегодня / С GaugeVision»: перетаскивание мышью и пальцем, ←/→ шаг 5 %, Home/End (`role="slider"`) | граница кадров следует за ручкой, подсвечивается список стороны, которой больше на экране | — |
| История PI-102 | прокрутка или кнопки этапов 01–08 | закреплённая сцена SVG 1200×760: прибор-герой переезжает между позициями (`[data-scene]`), слои этапов проявляются | `story.goTo(i)` |
| Щит | 1 / 2 / 4 / 8 / 16 приборов, клик по рамке прибора | смена кадра и таблиц, карточка прибора, предупреждение на 16 | `multigauge.setCount(n)` |
| Store-and-Forward | «Отключить связь», «Восстановить связь», «Сначала» | пакеты 4 в секунду, очередь блоками, досылка 24 в секунду в исходном порядке, счётчики | `resilience.cut()`, `restore()`, `reset()` |
| SCADA | — | цепочка «Камера → … → Рабочее место инженера» появляется по очереди | — |
| Диагностика | точки на экране пульта и список-дубль | карточка пояснения | — |
| Прогноз | «Повторить» | показания, затем прогноз, затем область неопределённости, затем отметки ETA и факта | `forecast.play()` |
| Оптимизатор | ползунок бюджета, пресеты, цель, флажки «обязательно» | плитки переезжают между «В плане» и «Отложено» (FLIP), сегменты шкалы бюджета, кривая Парето | `optimizer.setBudget(b)`, `setObjective(o)` |
| ТЗ | — | строки документа собираются каскадом при первом появлении; таблица обновляется при каждом новом плане (событие `gv:plan`) | `document.assemble()` |
| Эволюция | вкладки 1.0 / 2.0 / 3.0, клавиши-стрелки | смена панели | — |
| Экономика | девять полей ввода | пересчёт мгновенно, формулы раскрыты | — |
| Доказательства | раскрытие групп | счётчики ключевых цифр при появлении | — |

## Режим демонстрации

Подробно — `SHOWCASE_MODE_GUIDE.md`. Двенадцать шагов ставят страницу в воспроизводимое состояние через API
компонентов и прокручивают к самой демонстрации, а не к заголовку секции: на проекторе 1280×720 заголовок и
живая схема вместе не помещаются.

## Измерения

Прокрутка всей страницы шагами по 1/6 экрана, подсчёт кадров `requestAnimationFrame` (Edge, без троттлинга):

| Разрешение | Кадров в секунду | 95-й процентиль кадра | CLS | Длинных задач |
|---|---|---|---|---|
| 1920×1080 | 60 | 16,8 мс | 0,001 | 2 (до 195 мс, при запуске) |
| 1440×900 | 60 | 16,8 мс | 0,002 | 1 |
| 1280×720 | 60 | 16,8 мс | 0,003 | 2 |
| 768×1024 | 60 | 16,8 мс | 0,004 | 2 |
| 390×844 | 60 | 16,8 мс | 0,062 | 1 |

Длинная задача 160–215 мс — однократный монтаж 15 секций при загрузке; во время прокрутки длинных задач нет.

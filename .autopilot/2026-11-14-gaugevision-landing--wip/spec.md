# Спецификация: Лендинг GaugeVision AI

## Задача

У автора есть рабочий сервис компьютерного зрения для ТЭЦ, но жюри хакатона, инженер станции или работодатель видят только README на GitHub — длинный текст с таблицами. За несколько минут им нужно понять, что система делает, поверить, что она работает, увидеть, как устроена, и где у неё честные пределы. Сплошной текст этого не даёт, а красивый лендинг с выдуманными цифрами разрушит доверие инженера сразу.

## Решение

Одностраничный сайт-презентация в `./site`, который открывается двойным кликом с диска и работает на любом статическом хостинге. Сверху тонкая студийная панель переключает три принципиально разных варианта страницы: «Пульт», «Циферблат», «Протокол». Все три варианта на графите, с одними и теми же фактами и разными композицией и акцентами. В углу плавающая панель Tweaks меняет шрифты, оттенок фона (включая светлую «бумагу»), масштаб и набор изображений.

Каждый вариант проходит семь экранов в порядке брифа: hero с переключателем «Сырой кадр → Распознавание», полоса подтверждённых метрик с условиями замера, кликабельный разбор конвейера до значения в МПа/бар, сравнение «Было → Стало», SVG-схема архитектуры и стека, инженерные компромиссы и ограничения, финальный блок со ссылкой на GitHub. Каждая цифра на сайте взята из README, PRODUCT.md или кода, и рядом с ней указаны условия замера. Правила дизайна, выведенные из референсов, записаны в `site/design-system.md`.

## Решения по реализации

- **Стек:** чистые HTML, CSS и JS, классические скрипты в глобальном пространстве `window.GV`. ES-модули запрещены: по `file://` браузер их не загружает. Без фреймворков и npm-зависимостей — так требуют PRODUCT.md («Статика HTML/CSS/JS») и скилл (Track HTML).
- **Один источник фактов:** `js/content.js` — все тексты и числа; варианты и компоненты ничего не хардкодят. Так факты не расходятся между тремя вариантами, а проверка R11 становится механической.
- **Рендер вариантов из JS:** `index.html` — оболочка (студийная панель, `<main id="gv-root">`, Tweaks, noscript). Вариант рендерит всю страницу в `#gv-root` из `GV.content` и общих компонентов. Три полные страницы без трёх копий фактов.
- **Общие интерактивные компоненты** (hero-stage, конвейер, калибровка, EMA, сравнение, схема архитектуры, ограничения) пишутся один раз. Варианты стилизуют их своими CSS через `[data-variant]` и могут выбирать раскладку через опции. Так интерактив одинаково исправен во всех трёх вариантах.
- **Шрифты локально** в `assets/fonts/` (woff2, кириллица + латиница, лицензия OFL): Manrope, JetBrains Mono, Onest, IBM Plex Sans, IBM Plex Mono. Без CDN, потому что сайт должен работать офлайн, как и сам продукт.
- **Три варианта:**
  - **A · Пульт** — HUD-пульт: асимметричная сетка 12 колонок, слева заголовок, справа hero-stage в рамке с угловыми метками и телеметрией; метрики — горизонтальная телеметрическая полоса с `/01`; конвейер — горизонтальная лента этапов с панелью деталей снизу. Акцент холодный циан. Шрифты Manrope + JetBrains Mono.
  - **B · Циферблат** — по мотивам ref3–5, переведённым в тёмное: гигантская дуга шкалы с рисками через hero, оранжевая стрелка (`#FF5A1F`) — единственный акцент; композиция по центру; метрики — крупные контурные цифры как на ref4; этапы конвейера — риски на дуге. Шрифты Onest (жирный дисплейный) + IBM Plex Mono.
  - **C · Протокол** — инженерный протокол испытаний и даташит по мотивам ref6 и ref1: моноширинные метаданные, липкий индекс секций 01–07 слева, плотные таблицы с волосяными линиями; метрики — таблица «показатель · значение · условия»; конвейер — вертикальная шкала этапов с формулами. Акцент — холодное серебро с янтарным для статусов. Шрифты IBM Plex Sans + IBM Plex Mono.
- **Tweaks** управляет атрибутами `<html>`: `data-font`, `data-bg`, `data-media` и переменной `--ui-scale`, хранит их в localStorage `gv.tweaks` и сообщает об изменении событием `gv:tweaks`. Панель остаётся в итоговой сборке, потому что её прямо просит бриф. Правило скилла убирать её в продакшене здесь уступает брифу.
- **Масштаб:** все размеры в `rem`, корень — `font-size: calc(100% * var(--ui-scale))`.
- **Изображения:** реальные скриншоты из `site/assets/` кадрируются CSS-обёрткой (`overflow: hidden` + позиционирование), без внешних утилит — в окружении нет конвертеров изображений.
- **Проверка:** `node site/tests/check.js` без зависимостей. Числа из `content.js` ищутся в README.md/PRODUCT.md; все локальные `src`/`href` в `index.html` и `content.js` должны существовать; запрещённые слова отсутствуют; `id` секций и их порядок одинаковы во всех вариантах; в `js/` нет `import`/`export`. Визуальная проверка — Playwright: 3 варианта × 1440 и 390 px плюс «Бумага».
